# Development guidance

## Project intent and current scope

This project tracks music and event context at West Coast Swing events. Read `docs/project-overview.md` and `docs/implementation-plan.md` before substantial changes.

The repository implements Phase 1: package/CLI, inputs, replay, recognition windows/fixtures, track resolution, provisional plays, SQLite, scheduled context, run inspection/export, bounded AudD execution, upload planning, and independent evaluation. A bounded private trial and human-reviewed label correction are complete; acceptance limitations and unverified bumpers remain open. Phase 2 steps 1/2 implement diagnostics, offline reprocessing with explicit lineage/frozen catalog inputs, and parent/child comparison. Step 3a adds selected-error recovery from completed runs, durable request attempts, separate collection/analysis statuses, and recovery-aware reports. Step 3b1 recovers complete observations from terminal failed/interrupted analyses with explicit configured-window finalization. Step 3b2a recovers terminal saved prefixes with `completed_partial`, censored final occurrences and coverage-aware reports. Step 3b2b implements explicit incomplete-collection choices; step 3b2c implements immutable running-history checkpoints and isolated reconstruction. Step 3c implements bounded missing-suffix recognition and partial/full offline continuation; performance/maintainability consolidation precedes reviewed identity/schedule corrections. Read `docs/input-formats.md`, `docs/replay.md`, `docs/recognition.md`, `docs/aggregation.md`, `docs/persistence.md`, `docs/attribution.md`, `docs/provider-recognition.md`, `docs/evaluation.md`, `docs/diagnostics.md`, `docs/reprocessing.md`, `docs/recovery.md`, `docs/saved-recovery.md`, `docs/prefix-recovery.md`, `docs/collection-analysis.md`, and `docs/checkpoints.md`, and `docs/missing-recovery.md` before changing these contracts. Explain important architectural choices and their tradeoffs, since this is also a learning project. Present a concrete plan before substantial implementation. Do not implement later phases merely because they appear in the roadmap.

## Architectural rules

- Releases A/B of the [performance and maintainability consolidation](docs/performance-maintainability-plan.md) precede identity corrections. Release C completed its bounded storage decision: [keep the current format](docs/decisions/release-c-storage.md), with no C3 implementation. Preserve whole-database checkpoints, complete frozen seeds/plans and separate workspace ownership; do not prune evidence to match selected observations. Read the [operating guidance](docs/release-c-operating-limits.md) and rerun bounded storage controls before relying on a substantially larger declared trial workload. Its disk/time/memory requirements remain unassessed. Reviewed corrections can proceed. Release A is implemented: synthetic benchmarks, reusable migration fixtures, transaction-scoped read evidence, guarded collection/result cursors and audio hashing outside planner read transactions. Release B is implemented: shared dispatch in `collection_dispatch.py`, immutable method/report routing in `methods.py`, indexed interval evaluation, transaction-local catalog mutation rollback and focused `cli_*` modules. Preserve analytic opportunity counts, frozen-view index rollback and thin CLI coordination; command fault-injection hooks now belong to their handler modules. Reuse existing progress guards and domain validators; compare against the verified Release A baseline. Keep read caches within one read-only snapshot and preserve fresh writable validation. Collection revisions must retain dirty state across owned commits; another database writer conservatively stops later dispatch. Read [the benchmark guide](docs/benchmarks.md) before profiling or changing these tools. Reuse a frozen corpus for exact historical-output comparisons; do not regenerate or normalize historical evidence to make a refactor pass.
- Keep capture independent of analysis. Recognition or output failures must not stop recording.
- Define a shared timestamped audio-chunk representation behind an `AudioSource` interface. Start with `FileAudioSource`; future microphone and line-input sources must use the same downstream contract.
- Separate canonical `Track` identity from each `SongPlay` occurrence. Recognition-provider, Spotify, and Apple Music identifiers are optional external mappings.
- Collapse repeated detections within a continuous play. Preserve separate occurrences when a song plays again later.
- Store raw recognition results and inference evidence, including failures, alongside derived conclusions. Link detections and plays to recording chunks, timestamps, and offsets.
- Preserve provisional live predictions independently from post-event results and human corrections. Reprocessing must not silently erase the live evidence.
- Use timezone-aware timestamps and retain the event's timezone. Audio offsets must remain reproducible regardless of replay speed or machine clock.
- Keep source reading independent of replay pacing. Paced delivery uses monotonic deadlines at chunk ends; processing delays must not accumulate into repeated extra waits. Keep recognition windows independent of source chunk sizes.
- Treat schedules as expected context. Record attribution sources and confidence; a scheduled DJ or competition is not proof of actual activity.
- Allow unknown or ambiguous results. Do not invent provider confidence or present inferred heat, classification, timing, or DJ attribution as certain.
- The database is authoritative. Google Sheets, public web views, and playlists are optional outputs; their failures must not prevent core processing.
- Put provider-specific behavior behind narrow adapters. Do not build acoustic fingerprinting from scratch for the MVP.
- Fixture recognition requires an exact declared response for every full configured window. Missing fixture data is a setup error. Keep expected service failures distinct from no-match and unexpected programming failures.
- SQLite is authoritative for `process-fixture`; existing JSONL commands remain compatible diagnostics. Refuse diagnostic-output overwrites and never report incomplete/interrupted source coverage as full-grid completed; prefix execution has its own completed_partial status.
- Preserve version-1 recognition output. Aggregation emits version-2 raw-plus-derived evidence with explicit policy versions, unresolved conflicts, gap evidence, and estimated window-envelope boundaries. Never force exclusive song intervals or close an interrupted open play as normal EOF.
- Database-backed runs reuse persistent Track IDs. The existing JSONL-only commands use fresh in-memory catalogs. Preserve immutable historical resolution snapshots as canonical mappings grow.
- Commit raw results before derivation, catalog additions with their resolution decisions, and closed plays with all evidence links. Never hold write transactions during recognition or replay waits. A partial `running` row is unconfirmed, not successful or automatically resumable.
- Keep database schema versions distinct from diagnostic versions. New databases use schema 9; version-1/2/3/4/5/6/7/8 writable opens migrate atomically, while read-only opens preserve versions 1/2/3/4/5/6/7/8/9. Original exports stay version 2/3; earlier offline-derived exports use version 4; selected-error analyses/descendants use version 5; saved-evidence recovery/descendants use version 6; saved-prefix recovery uses version 7 with a distinct run_partial_completed terminal record; explicit incomplete-collection analyses/descendants use version 8; checkpoint analyses/descendants use version 9 (comparison 6, diagnostic/evaluation 7); missing-window analyses/descendants use version 10 (comparison 7, diagnostic/evaluation 8), retaining checkpoint provenance where applicable. Enable foreign keys, refuse unsupported databases, and inspect/export through read-only consistent snapshots.
- Attribute each play from its saved snapshot with independent session/DJ cardinality decisions. Preserve all ambiguous candidates, missing-schedule/uncovered distinctions, schedule-only provenance and unknown numeric confidence. A context change does not split a song occurrence or overwrite scalar live/final/review fields.
- Use integer sample-start ceiling for schedule boundaries and retain original off-grid timestamp evidence. Save a play and its entire context atomically; require full context coverage only for runs declaring the attribution policy. Do not backfill terminal runs or rewrite historical exports.
- Keep `plan-audd` and `plan-recovery` offline and token-free. Only explicit `process-audd`, `recover-audd` or `collect-missing-audd` execution uploads audio. Preserve fixed HTTPS, exact WAV encoding, explicit budget preflight, the 12-second/8,000,000-byte profile, finite timeouts, and no automatic retries/redirects. Keep credentials out of configuration/evidence/logs; redact echoes and retain digests rather than malformed body text.
- A fatal service failure must yield its error result before stopping on the next iteration. Commit raw evidence, preserve earlier plays/context, issue no later request, and never finish an interrupted open play as normal EOF. Recoverable window errors remain distinct from no-match.
- Evaluate saved evidence read-only without provider calls, using independent source-hash-bound labels. Preserve explicit denominators, exclusions, alias ambiguities, censored boundaries, and partial-run coverage. Mocked results establish calculation/integration behavior, not real acoustic accuracy or Phase 1 acceptance.
- New diagnostics use controlled text/facts and explicit transport types, never arbitrary exception/provider strings. Notify live observers only after raw commit; optional diagnostic I/O failure must not undo analysis. Diagnose saved runs read-only without tokens, source files, migration, or provider calls. Keep historical unknown subtypes unknown and distinguish saved outcomes, process attempts, stop directives, terminal state, and unknown billing.
- Offline reprocessing requires completed, validated evidence; perform read-only preflight before writable opens. Commit each unchanged copied outcome with its immediate-parent link, use the exact saved timeline/schedule, and record zero new provider requests. Inherit audio hashes without claiming fresh verification. Keep original rows, snapshots, and exports unchanged.
- Freeze resolution lookups: capture the current catalog for an original parent, inherit the saved starting seed for a derived parent, and merge compatible writes without losing shared mappings. Offline plays/context use `offline_reprocessed`, remain unreviewed, and do not fill final inference. Compare completed immediate parent/child pairs through support links; separate musical conclusions from audit differences and independent-label accuracy. Pure-derived diagnostic/evaluation reports use schema 2; selected-error reports use schema 3; saved-evidence recovery reports use schema 4; prefix diagnostic/evaluation reports use schema 5 and comparison schema 4; originals retain schema 1.
- Selected-error recovery requires a completed validated parent, explicit saved AudD error ordinals and ceiling, bound plan, and full audio/hash/format checks before writable processing. Prepare exact selected spans privately before uploads. Commit dispatch intent before HTTP as a mandatory boundary; never suppress its storage failure or hold a transaction during HTTP. Preserve saved outcomes before stopping on fatal errors. Intent does not establish provider receipt or billing. Every invocation starts a new session, never an automatic resume.
- Separate collection from derivation. `analyze-recovery` needs a completed nonfatal collection and uses no audio/token/network. Select only that session's new outcomes for planned slots and exact parent payloads elsewhere; retain all attempts. New recovery track IDs use the versioned frozen-seed/stable-origin allocation policy, inherited by pure descendants. Separate explicit selection and checkpoint methods implement 3b2b/3b2c; bounded missing-window recognition uses its own 3c contract.

- Default complete saved-evidence recovery requires complete exact window coverage and a terminal failed/interrupted parent; reject running/partial/empty-grid/explicit-fatal inputs before writes. Freeze plan/catalog/origin provenance and use a distinct saved_evidence_recovery_v1 method; existing methods retain completed-parent rules. Preserve unsuccessful originals and make zero audio/token/network accesses.
- Inherit saved_complete_grid_v1 finalization through descendants. Final open plays close as planned_windows_complete with historical_termination_unknown; never infer historical EOF or extend envelopes into unrecognized tails. Partial child coverage remains explicit. Rebuild schema dependencies with foreign keys enabled and preserve all historical report/export bytes.

- Prefix recovery requires explicit coverage mode, a proper nonempty contiguous prefix and terminal nonfatal failed/interrupted input. Bind input K and full grid N in the frozen manifest; distinguish copied M, unobserved N-K and uncopied K-M. Preserve the source timeline and do not synthesize missing outcomes. Only validated saved_prefix_recovery_v1, checkpoint_prefix_recovery_v1 and partial missing_window_recovery_v1 methods can complete as completed_partial. Finalize its still-open final play with end_of_saved_prefix and both censoring/historical-termination flags; never infer EOF. Exclude that predicted end from timing denominators independently of label censoring. Existing completed-only methods refuse partial-success outputs; repeat the original frozen plan to reanalyze, or explicitly extend an eligible prefix through the separate missing-window method. Step 3b2b now supports explicit choices from terminal nonfatal failed/interrupted collections with completed parents; running histories require the implemented immutable checkpoint contract and an isolated owned working database; ordinary recovery still refuses them.

- Incomplete-collection analysis uses its own manifest/method. Require an explicit saved retry or retained-parent choice for every collection slot, preserve all attempts, and never silently fall back. Full selected grids can complete while the collection stays failed/interrupted; retain parent termination provenance. Old analyze-recovery still requires a completed nonfatal session. Freeze the session seed and stable origins; preserve historical formats. New collection comparison uses schema 5 and diagnostic/evaluation schema 6.

- Checkpoint capture uses bounded SQLite online backup, never a filesystem copy of a live database. Read subject/catalog/attempt facts from the captured image, seal its bytes/manifest, and preserve the original status and writer. Only the published manifest makes a bundle usable. Analyze a verified closed copy in a separately owned database; refuse the live original, bundle paths and other checkpoint workspaces as targets. Never repair captured running statuses to fit old validators. Changes in the live original do not change a checkpoint; edits to its captured base do. Prefix checkpoint evaluation preserves independent prediction/label censoring. Include capture/ownership provenance in new profiles while preserving every historical format.

- Missing-window recovery accepts only validated completed_partial saved/checkpoint/continuation prefixes with saved AudD/hash evidence. Plan a bounded contiguous K+1..E range and explicit ceiling; freshly verify exact WAV bytes before writes/uploads. Dedicated source/frame slots and nullable parent links never invent missing outcomes. Preserve older retry-table constraints. Commit intent before HTTP, outcome before continuing, and keep collection separate from frozen offline derivation.
- Missing-window analysis consumes one terminal nonfatal collection's committed contiguous continuation. Validate L independently of original K/N; successful L<N is completed_partial with censored prefix closure, L=N uses configured-grid closure with unknown historical EOF. Rebuild the whole selected sequence, preserve earlier conclusions, and keep M/L/N distinct on failure. No automatic resume, interior holes, cross-collection union, implicit live imports or checkpoint capture for new unconfirmed running collections.
- Preserve missing-attempt origins, frozen catalog identities and workspace ownership through descendants. New comparison aligns configured slots and distinguishes added observations from changed outcomes; no fictional parent result/resolution is allowed. Report actual selected origins even after later retries replace continuation observations, keep request/analysis/coverage facts separate, and preserve every earlier format byte.

## Audio and publication constraints

- Do not start with dedicated hardware. Use prerecorded event audio first.
- Any eventual capture connection to a mixer must be a passive branch/feed. Never put this system inline between DJ equipment and the PA.
- Preserve local source audio for reprocessing. Future capture should use timestamped lossless chunks, initially targeting about 10–15 minutes per chunk.
- Never publish raw ballroom recordings or commit private recordings, credentials, or generated databases. Use `data/` for local artifacts and environment variables for secrets.
- Analyze actual event audio. Do not use Spotify or Apple Music streams as recognition or machine-learning input.
- Publish metadata and licensed-platform links. Full music playback is outside the initial public app scope.
- Attendees should not need accounts or authorize music services. Any eventual playlist maintenance belongs to a backend-owned integration.

## Working practices

- Prefer small, understandable Python modules and explicit contracts over speculative frameworks or distributed services.
- Keep external calls out of deterministic tests. Use synthetic recognition responses and small synthetic schedules; make credentialed provider checks opt-in.
- Test behavior where it matters: timestamps, deduplication, repeated song occurrences, unknown results, schedule boundaries, provenance, and persistence.
- Run checks appropriate to the change and report what actually ran. Install with `.\.venv\Scripts\python.exe -m pip install -e '.[dev]'` and test with `.\.venv\Scripts\python.exe -m pytest -q`. Test the installed package rather than injecting `src/` into the Python path.
- Keep `README.md` accurate as setup and run commands become available. Update the overview and plan when accepted decisions change.
- Defer heat inference, speech transcription, advanced classification, public deployment, music-service exports, and hardware until their planned phase.
