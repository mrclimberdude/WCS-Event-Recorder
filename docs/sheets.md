# Optional Google Sheets snapshot mirror

The optional mirror renders a bounded recent metadata snapshot and reconciles it into one explicitly designated rectangular range. SQLite remains authoritative. No connector, OAuth consent flow, spreadsheet creation or real external activation is included in offline verification. An external write requires a separately authorized destination and a short-lived OAuth bearer token supplied by the operator. Attendees never authorize music or Google services.

`render_sheet_snapshot(configuration, max_rows=201)` takes a `ViewConfiguration`, performs full selection validation, and then obtains a fresh bounded projection. It refuses private previews. Its JSON result has `schema_version: 1`, a stable opaque configured-view-alias `view_id`, selected `generation`, fourteen fixed `columns`, scalar `rows`, and `has_more`. The renderer reads `min(configuration.page_limit, max_rows - 2)` occurrences, at most 200. `has_more` explicitly identifies a truncated recent snapshot; false does not turn a partial analysis into complete source coverage. The selected occurrence's censoring and historical-termination uncertainty remain in the cells. Generation distinguishes explicit interpretation/room/run changes while the configured alias keeps mirror ownership stable.

The fixed columns are `view_id`, `generation`, `occurrence_key`, `event`, `room`, `timezone`, `title`, `artist`, `start_time`, `end_time`, `timing`, `censored_end`, `scheduled_context`, and `uncertainty`. Start/end are aware ISO recording-clock timestamps expressed in the saved event timezone. Each derives from the saved UTC source origin plus its absolute frame offset divided by sample rate, using exact rational arithmetic and rounding once to microseconds, as in `RecordingSource.time_at_frame`. Conversion back to the event timezone preserves midnight crossings and DST offset changes; processing timestamps never enter these columns. For example, two seconds after `2026-11-01T01:59:59-04:00` in New York is `2026-11-01T01:00:01-05:00`.

Context and uncertainty cells contain compact safe JSON. Uncertainty retains `start_frame`, `end_frame`, `sample_rate`, `analysis_status`, the selected analysis's complete safe `coverage` object, and `review_kind`, alongside the allowlisted occurrence flags. The coverage facts remain explicit even when a selected partial analysis's last visible occurrence has no censored end. Frames/context offsets remain reproducible. Context is scheduled/expected, never proof of actual DJ/activity, and identity/schedule review does not establish reviewed occurrence timing. This snapshot does not claim exact song boundaries or currently playing music. It includes neither audio nor playback links, private IDs/paths, provider/error bodies, reviewer notes, catalog seeds or tokens. The snapshot is intended as a bounded operational mirror rather than a complete metadata-view export.

`SheetsDestination(spreadsheet_id, tab_name, max_rows=201)` confines operations to quoted `'TAB'!A1:N201` (with the explicitly configured row count). Spreadsheet IDs allow only letters, digits, underscore and hyphen; tab names allow letters, digits, spaces, underscore and hyphen. **The row count includes one ownership row and one header row:** the default has capacity for 199 occurrences. Counts from 3 through 202 are accepted. Columns remain A:N. Supply a dedicated tab/range with enough existing rows/columns; the adapter never creates or resizes a sheet. Unrelated rows, columns and tabs are untouched.

`HttpSheetsTransport(access_token, client=None)` supports only exact-range `read(destination)` and `write(destination, grid)`. It uses fixed `https://sheets.googleapis.com/v4/spreadsheets/…/values/…`, `GET` with `valueRenderOption=FORMULA`, and `PUT` with `valueInputOption=RAW`. FORMULA detects existing formulas even when they evaluate to empty cells. RAW keeps a title starting with `=`, `+`, `-`, or `@` as literal text. Google documents [values operations and RAW input](https://developers.google.com/workspace/sheets/api/guides/values). The adapter performs no append, redirect, automatic retry, audio access or recognition request. Its own HTTP client disables environmental proxies and uses a transport with zero retries; an injected client is for controlled tests and must not add retrying transport behavior. Connect timeout is five seconds and other operation timeouts are ten seconds. Response and grid JSON are bounded to 1 MiB. Malformed, oversized and non-JSON responses produce controlled errors; provider text and authentication headers are excluded from state/results.

A successful read must contain a valid [Google ValueRange](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values#ValueRange): the exact requested tab and rectangle, `majorDimension: ROWS`, and optional bounded scalar `values`. The returned tab may be quoted or unquoted. Google can omit `values` for an empty range; that establishes emptiness only after the rest of the envelope validates. Missing metadata, wrong bounds/dimension, unknown fields, duplicate JSON keys and malformed grids stop reconciliation with controlled `invalid_response`, leaving durable pending state and making no replacement after the rejected read. An unrelated successful JSON response cannot authorize a first claim.

No OAuth library or browser flow is bundled. A future explicitly authorized caller can supply an environment-owned short-lived access token. The token must already have access to the designated file; this adapter neither acquires nor refreshes tokens. Prefer a suitably granted per-file `drive.file` scope where the operator's authorization setup supports it. Google explains that [Sheets scopes apply to the spreadsheet, not an individual tab](https://developers.google.com/workspace/sheets/api/scopes). Application range confinement does not narrow the OAuth grant itself. Do not store the token in selection configuration, dry-run artifacts, CLI arguments, delivery state or source SQLite.

`publish_sheet_snapshot(snapshot, destination, state_path, transport, max_requests=6, max_attempts=3, deadline_seconds=60, claim_empty_range=False, protected_database=None)` owns a separate local state file. Rendering/validation finishes and its database transaction closes before this function performs network calls or waits. Before creating any state or lock, output-path validation rejects SQLite `-wal`, `-shm` and `-journal` names, including nonexistent sidecars. Passing `protected_database` also rejects the selected main database; the CLI passes it. Existing non-JSON/binary databases remain refused by the state reader even without this argument. State is atomically replaced and protected by an exclusive adjacent `.lock` file. It binds the exact destination/range, alias and random owner ID, records a desired digest before network I/O, and retains pending/delivered digest/generation plus a controlled last error. Symlink state, changed destinations/aliases and another live local lock are refused. Keep state outside the source database and retain it between invocations. A stale lock after a crash requires operator investigation/removal once no publisher is running; it is never automatically broken.

Each invocation reads the range before replacing it. The first row carries the schema marker, local state owner, alias, generation and bounded/truncated indication. A missing or mismatched owner is refused. First claim requires `claim_empty_range=True` and an entirely empty range; it cannot take over existing data or another publisher's marker. A successful update replaces the entire fixed rectangle using RAW values, including empty padding. Shorter/new generations therefore remove obsolete managed rows without leaving earlier songs beneath the snapshot. The header/marker are always rewritten with the same fixed schema. This is idempotent replacement, never append.

After a timeout or unknown commit, the next attempt/restart reads back first. An exact desired grid is confirmed without writing again; a differing grid owned by this state is replaced. A successful write is followed by readback before delivery is recorded. Authentication/permission, configuration, redirect, protocol and permanent HTTP failures stop retries. HTTP 429, 5xx, transport failures, timeouts and readback mismatch are retryable within explicit request/attempt limits, with exponential delays plus bounded jitter. Google recommends [truncated exponential backoff for quota failures](https://developers.google.com/workspace/sheets/api/limits). No request or retry sleep starts after the configured scheduling deadline; an already started request may finish under its finite HTTP timeout. A returned `pending` result includes controlled category/counts and leaves reconciliation state intact. It is not successful delivery and does not stop the independently invoked collector.

An additional destination lock uses `tempfile.gettempdir()/wcs-recorder-sheets-locks/<digest>.lock`, where the digest binds spreadsheet ID and case-folded tab name. It deliberately ignores configured row count, since all managed ranges overlap at A1. Atomic exclusive creation fails immediately without waiting; two publishers on the same host/user temporary-lock namespace cannot simultaneously claim the same tab even with distinct state paths or row limits. Independent destinations can proceed. A symlink, junction/reparse point or invalid shared lock directory is refused. Cleanup checks the owned inode and nonce and never removes a replaced lock; crashes leave a stale lock for operator investigation. The adjacent state lock remains a separate guard against reusing one local state file.

A second state path also sees and refuses an established different remote owner. The Sheets values API does **not** provide a compare-and-set/distributed lock here: publishers on different hosts or isolated temporary namespaces could both read an empty range before either writes. Operate exactly one publisher per destination across those boundaries, and coordinate first claims explicitly. The marker guards accidental ownership conflicts; it is not distributed mutual exclusion or a hostile-edit guarantee. Retain one state file and stop the old publisher before switching operators. A changed alias/destination needs a separately reviewed ownership decision; the code never silently resets ownership.

Dry-run JSON contains the safe snapshot only and must be exclusively created; it needs no destination, token, network or state. It is a review artifact, not evidence of delivery or permission to publish. Tests use synthetic SQLite histories, memory transports and HTTPX mock transports. They cover recording-clock ISO conversion across midnight and both DST transitions, rational fractional-frame rounding, partial coverage independent of occurrence censoring, fixed RAW ranges, formula-like titles, padding/corrections, unknown-commit restart, quota/backoff/auth/timeout/redirect/response bounds, local ownership/state/locks and a collector committing while output fails. These establish deterministic software behavior, not a credentialed integration or event-publication acceptance claim.
