# Release C storage measurements

Status: complete; C4 verification passed. The selected C2 outcome is to keep the current format within the tested scope. No new storage format or full-event throughput is claimed.

## Protocol and scope

Artifacts live under `data/benchmarks/release-c-20261024/`. All source databases, PCM and provider outcomes are synthetic. Socket/DNS connections are blocked. The original A/B corpus is never used as a writable fixture. The production package hash is `a388f40187d556311312b5fa13a29a71c3217539f01a84ec6c6d81b6cb11646a`, matching the verified Release B implementation.

The developer limits are 8 GiB generated bytes, 10 GiB minimum free space, 600-second workers, at most 64 cases and the existing 10-second capture timeout. They bound these experiments, not user event acceptance. Each operation has three fresh-process ordinary samples, a separate work-counting pass and a separate allocation pass. Input templates are hashed before/after; mutating targets are private and recreated for every pass. Phase timings are inclusive; encoding/diagnostic writing and setup are separate. Logical hash bytes are not physical device I/O.

`standard` has 15 cases / 112 protected files, about 297.22 MiB including construction templates. `mapped-smoke` has seven cases / 28 protected files, about 8.42 MiB, and exercises complete seeds with external mappings. Construction copies are developer overhead and are excluded from the per-case retained-storage figures below. The standard raw checkpoint axes use unmapped seeds; mapped-seed behavior has its separate control.

The standard raw prefix has 500 of 1,000 observations and a 500-track seed. The unrelated sweep adds terminal no-match histories with 500 observations each; selected subject, source/configuration/schedule and seed digests remain equal. Catalog size is a separate changed semantic input. Captures 1/3/10 have the same unchanged subject but distinct checkpoint/owner identities. Retry and continuation families retain their actual eligible states, origins and seeds; catalog counts can include compatible additions made by their construction.

The original depth fixtures had varying synthetic adapter elapsed times and independently created schedule IDs. Their per-workflow measurements are retained as preliminary results, not a strict isolated ancestry comparison. `scripts/release_c_controls.py` creates the replacement depth control with one precreated source/schedule and only the mock AudD adapter clock fixed. Publication requires equal source, outcome and seed digests across 0/1/3 ancestors. Measured operation clocks, budgets, production code and original evidence are unchanged.

All 15 measured input databases have zero freelist pages. The growth is retained rows/indexes/documents, not evidence that VACUUM would remove large amounts of free space. No original or published image was compacted.

The no-match unrelated sweep increases the input DB by about 21.86 MiB at 100 histories and the retained case by about 65.56 MiB while selected-input digests stay fixed. Whole-database capture/workspaces amplify that growth. A larger active seed is also a real input cost: it cannot be reduced to only resolved tracks without changing lookup behavior.

## Timing, work and memory

All **120 final jobs / 600 isolated passes** succeeded, including three ordinary, one instrumented and one allocation pass per job. Raw reports are `standard-inventory-export.json` (30 jobs), `standard-checkpoint-axes.json` (20), `standard-checkpoint-paths.json` (6), `standard-checkpoint-families.json` (8), `standard-continuations.json` (8 preliminary workflow jobs), `mapped-smoke-all.json` (39) and `controlled-ancestry.json` (9). The latter replaces the preliminary ancestry comparison for depth attribution. The three controlled cases contain 15 protected files and pass equal source/outcome/seed digest assertions. All measured package hashes match the verified B package; construction/tool hashes are recorded separately.

The completed checkpoint axis batch measured base capture at 0.0839 seconds and 100-unrelated-history capture at 0.5072 seconds. Fresh reconstruction measured 5.3644 seconds for the 500-track seed and 10.9163 seconds for 10,000 tracks. These are production API operation medians, not cold disk or complete installed-command latency. All capture samples in that batch stayed within the unchanged timeout; reconstruction is a separate operation.

Disk observations occur at declared phase/link/unlink boundaries. The reported copy/publication bound applies to an unchanged image; it excludes derived rows, manifests and journals. The experiment budget supplies additional conservative headroom but does not establish a continuous per-operation journal high-water mark. Working-set snapshots include imports/setup/allocator state, and process peaks are lifetime peaks. Traced Python peaks cover only the measured operation.

### Verification I/O and other branches

Fresh checkpoint analysis hashes the full image three times and copies it once inside its measured API. That is 2,469,888 logical hash bytes for the base image and 71,233,536 for the 100-history image. Source-audio hashing is zero in all measured offline operations. The base and unrelated variants have identical analysis SQL/JSON counts (34,558 / 45,874), so their additional image I/O is distinct from target-evidence decoding. Capturing a current catalog increases SQL work with seed size; C records that cost without redesigning catalog lookup or pruning seeds.

Other ordinary medians: existing-workspace analysis 5.7759 seconds for the base prefix and 11.3712 for 10,000 tracks; full-grid checkpoint analysis 11.7648; retry-collection checkpoint analysis 16.4387; full continuation analysis 17.7150. Capture timeout and analysis duration are separate.

Largest traced operation peak was 45.81 MiB. Normal working sets in the tables are post-operation snapshots, not native high-water marks; allocation-pass working sets include tracing overhead and are reported separately in raw results. The largest observed experiment-root logical footprint was about 387.18 MiB, including developer fixtures, reports and disposable jobs. This is not a per-operation product staging bound.

### Separate cleanup control

`cleanup-controls.json` measures three deletions each of verified owned closed-file copies. Median cleanup seconds were 0.01873 for the base copy, 0.01719 for the 100-history copy and 0.01741 for the 10,000-track copy. Copy/setup is excluded. These measurements are diagnostic cleanup controls after main timing; they do not establish every SQLite journal deletion cost, crash durability or physical blocks immediately reclaimed.

## Interpretation and remaining work

Whole-database duplication is measurable and can dominate retained case bytes. A/B runtime improvements did not remove it. Conversely, fixed-subject inspection/export work stays bounded despite additional histories, so these storage measurements do not justify reopening A/B's read/progress/evaluation algorithms.

The current samples remain small relative to the declared developer disk/deadline envelope. An event/evidence archive could remove unrelated histories, but preserving complete seeds, attempts, provenance and ownership requires a new explicit boundary. Its net bytes, staging/verification cost and maintenance burden are not established by row or JSON deduplication counts.

There is no specified larger-trial disk/time/memory requirement. A keep-current decision can therefore be scoped to these tested developer workloads, with explicit remeasurement triggers. It cannot establish readiness for an entire long livestream, larger PCM preparation, more rooms, arbitrary ancestry or new correction dependencies.

## Final verification

The full installed-package regression passed **1,549 tests in 406.80 seconds**, retaining every 1,519-case B test identity and all 230 saved-recovery migration cases. Thirty added cases cover storage tooling and the controlled fixture builder, including missing closure, independent reconstruction/evaluation and a real writer continuing after capture. The original corpus still contains 35 histories, 174 exact reports and 228 unchanged protected files; all 32 installed CLI help outputs match the B baseline. Zero real provider requests were made.

Raw gate records are `release-c-final-pytest.txt`, `release-c-final-tests.xml` and `final-corpus.txt` under the artifact directory above. Final package, benchmark-module, entry-script and supplemental-control hashes match their measured versions. Documentation links, Python syntax and whitespace checks passed.
